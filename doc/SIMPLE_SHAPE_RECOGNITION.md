# 简易目标识别实现说明

## 1. 实现范围

本功能对应赛题的简易目标识别扩展，不运行 YOLO。适用场景：

- 纯白背景；
- 实心矩形、圆形、三角形；
- 图形允许任意颜色和任意旋转；
- 图形完整位于画面内、互不重叠；
- 一帧最多输出 5 个目标；
- 标注为 3 像素包围框和 `RECT`、`CIRC`、`TRI` 英文类别标签。

目标颜色需要与白背景存在足够色差。白底上的纯白目标没有可观测对比度，原则上无法仅靠图像区分。

## 2. 数据流

```text
SC431HAI RAW10
  -> MIPI CSI-2 / debayer
  -> 1 pixel/clk RGB
  -> 全分辨率 Canny 边缘流
  -> 缺口修复的水平 edge-run FIFO 与 16 标签 union-find 连通域
  -> 邻近碎片合并
  -> 几何分类与坐标缩放
  -> 逐帧跟踪、坐标死区与类别迟滞
  -> 原图 + 包围框 + 类别标签
  -> HDMI
```

识别与模式1~3共用同一条全分辨率 Canny 边缘流。Canny 边缘同时用于显示和目标轮廓分析，不再增加颜色前景压缩链路。

## 3. 前景提取

识别直接使用 Canny 流水线的 `edge_valid/edge_paint/x/y`，不再生成 480×270 彩色前景压缩图。ROI 默认只忽略左右各10像素、上下各10像素，在去除摄像头/显示画面最外侧边框的同时，把靠近画面边缘的有效目标区域保留下来。

边缘像素在光栅顺序中合并成水平 run，并写入一个512项 FIFO。另一侧 FSM 使用16个内部标签、8个行区段进行8邻接连通域合并。每行结束时根据同一标签左右轮廓之间恢复扫描线填充跨度，因此仍能使用面积/填充率分类，而不受Canny线宽影响。

行填充采用逐run流水：`FILLROW → FILL_SCAN(每周期1个run) → FILL_CALC(减法和中点) → FILL_MUL(跨度乘y与中点乘跨度) → FILL_ACC(累加)`。最新上板报告的最差路径为 `cu_x1[0][9] → row_fill_sumy[20]`、36级逻辑、WNS=-4.568 ns；旧实现把8个run扫描、边界选择、减法和两级乘法全部压在同一周期。新结构把边界选择和算术分别寄存，最差路径被拆成“8选1比较”和“单级减法/单级乘法”两段。

Canny双阈值在弱边上仍会产生短缺口。若把每个缺口都当作轮廓终点，同一个矩形或三角形会被拆成多个片段，片段面积和质心不再具有原图形的几何特征，这是矩形/三角形互相误判的主要来源。当前前端增加三级修复：

- 同一行两个edge-run之间不超过6像素时合并；
- 某一行短暂漏检时，上一行run最多保留3行用于继续连接；
- 帧末将包围框横纵间距都不超过8像素的邻近连通域合并后再分类。

## 4. 连通域和分类

检测器按行提取前景区段，采用 8 邻接扩展把相邻两行重叠区段合并。标签父指针表支持 16 个内部标签、每行 8 个区段，最终发布最多 5 个有效目标。每个连通域统计面积、质心、包围框和质心相对包围框中心的偏移。

一次区段闭合被拆成 `PREPARE → UNION(逐标签) → ADD` 三个状态：`PREPARE` 只查找上一行区段直接对应的根标签，`UNION` 每周期处理一个标签并展平父指针，`ADD` 再把当前 run 统计加入根标签。该结构消除了从上板报告中定位到 `pv_label → acc_x1 CE` 的 `-7.930 ns` 长组合路径。

帧末分类拆为 `FINAL → FEAT_MUL → FEAT_DIFF → FEAT_THRESH → CLASS`：前级读取最终组件并计算包围框面积、填充区域质心偏移；`FEAT_THRESH`把分类所需的比例乘积全部寄存；`CLASS`只执行比较。旧报告中的最差路径为 `f_bw[6] → work_class[0][0]`、24级逻辑、WNS=-0.926 ns，本次已从结构上打断该路径，最终WNS以重新综合报告为准。

原始检测随后进入 `shape_tracker`：新目标至少匹配两次才显示；框坐标变化小于 32 像素时保持原位置；人工移动超过死区时直接更新到新位置；短暂漏检保持上一帧框。类别使用泄漏计数迟滞：错误观测累计10次才切换，单次正确观测只把计数减1而不是清零。按30~60 fps计算，稳定换类约需0.17~0.33秒，满足1秒内重新识别的要求。

跟踪器采用逐目标、逐候选的 FSM，每个时钟只比较一个跟踪槽。上一版把 5×5 目标匹配全部放在 `frame_done` 单周期内，Efinity 报告的最差路径为 `track_y0 → track_x1`、95 级逻辑、WNS=-20.252 ns；该时序违例会直接造成框跳和周期显示异常，现已在结构上消除。

分类顺序：

1. 圆形：包围框接近正方形且填充率接近 `pi/4`；
2. 三角形：必须同时满足填充率不超过62.5%、不低于30%、且质心相对包围框中心明显偏移。下限用于拒绝断裂矩形片段，质心条件用于区分低填充率的菱形矩形；
3. 矩形：其余完整凸区域。

分类使用每行左右轮廓之间重建的填充跨度，因此不再依赖固定采样网格。

为控制 Ti60F225 的 XLR 逻辑资源，最终版本移除了二阶矩/64 位方差乘法链，并将连通域内部标签限制为 16 个、每行区段表限制为 8 项。矩形、正方形多角度、圆形和三角形回归均通过。

## 5. 显示模式

KEY1 循环：

| 模式 | 功能 |
|---|---|
| 0 | 彩色原图 |
| 1 | 全屏二值 Canny 边缘 |
| 2 | 左右分屏 |
| 3 | 原图叠加红色 Canny 边缘 |
| 4 | 原图叠加目标识别框和类别文字 |

模式 4 下，LED4～LED7 显示检测目标数量的四位二进制值，例如只有 1 个目标时 LED4 亮。若 LED 显示 `0001` 但画面没有框，应检查叠加坐标/显示模式；若显示 `0000`，应检查白背景、目标色差和前景阈值。

当前识别输入为模式1使用的同一条全分辨率 Canny 边缘流。KEY2/KEY3 修改 Canny 阈值时，模式4的识别结果也会同步变化。

无法连续按键时，可先把 `ui_control` 的 `MODE_DEF` 临时改成 `3'd4` 上电直达识别模式。

## 6. 主要文件

- `rtl/image/shape_edge_detector.v`：全分辨率 Canny edge-run、连通域、扫描线填充和分类；
- `rtl/image/shape_tracker.v`：目标匹配、时间确认、坐标稳定和短暂漏检保持；
- `rtl/image/shape_overlay.v`：彩色框线和 5x7 字库叠加；
- `rtl/image/edge_detect_1ppc.v`：识别链路及模式 4 顶层接入；
- `rtl/image/ui_control.v`：五档显示模式按键控制；
- `sim/tb_shape_edge_detector.v`：矩形、圆形、三角形轮廓识别测试；
- `sim/tb_shape_edge_rotation.v`：22组旋转矩形、菱形、三角形、圆形及短缺口回归；
- `sim/tb_shape_overlay.v`：框线和文字测试；
- `sim/tb_edge_shape_mode.v`：模式 4 的完整链路测试。

## 7. 仿真

在工程根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File sim\run_canny_sims.ps1
```

当前回归结果：

- 原有饱和度、Canny、5 行对齐、分屏和红色边缘叠加测试全部通过；
- 单帧矩形、圆形、三角形轮廓识别通过；
- 22组任意旋转及Canny短缺口分类通过；
- 模式 4 完整 Canny 轮廓链路输出正确矩形框；
- 人工移动超过坐标死区时跟踪框立即更新，静止目标的小幅抖动被抑制。
- 类别持续变化需10帧确认，间歇错误不会立即改变标签。
- 行区段 FIFO 使用512项深度，避免全帧二值图存储。

## 8. Efinity 流程

以下文件已经加入 `ti60f225_oob.xml`：

```text
rtl/image/shape_edge_detector.v
rtl/image/shape_tracker.v
rtl/image/shape_overlay.v
```

在 Efinity 中打开 `ti60f225_oob.xml` 后：

1. 执行 Synthesis；
2. 检查是否有 SystemVerilog 数组或乘法器实现告警；
3. 检查 WNS、LUT、FF、BRAM、DSP 使用量；
4. Synthesis 无错后执行 Place & Route；
5. 下载比特流，按 KEY1 切换至模式 4；
6. 用白纸作背景，分别放置彩色矩形、圆形、三角形，检查框、类别和帧间稳定性。

V1提交工程设置 `USE_DEBUG=1`，使用工程内已有的手动 `debug_edb_top`实例提供VIO/LA，XML中的Debugger auto instantiation保持关闭以避免重复插入调试核。LA0用于观察MIPI像素与DDR校准状态；当前debayer仍使用已验证的固定白平衡常量，VIO的R/G/B增益探针暂不参与画面，`gamma_sel`继续作为CFA相位调试探针。

修改前冻结工程基线为约 12065 LUT、9344 FF、4 DSP48、10 DSP24，WNS 为正；本次新增识别链路仍需要以 Efinity 最终报告为准。

## 9. 上板验收

建议按以下顺序验收：

1. 单个轴对齐彩色矩形；
2. 单个旋转矩形；
3. 单个圆形；
4. 单个三角形；
5. 三个类别同时出现；
6. 五个目标同时出现；
7. 改变图形颜色和位置，确认包围框连续稳定；
8. 改变拍摄距离，使最小目标约为画面宽度 10%。

若出现漏检，先检查模式1中的 Canny 边缘是否完整闭合；若轮廓断裂，检查 Canny 双阈值；若小目标被删除，检查 `MIN_SIZE` 和 `MIN_EDGE_PIX`；若类别混淆，检查扫描线填充跨度是否正常。
